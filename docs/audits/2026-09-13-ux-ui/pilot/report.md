## Проверенные границы и оговорки

- Игроки A/B не входили в приложение во время первой игры. Физическая передача телефона человеку не выполнялась: проверено продолжение той же авторизованной сессии без запроса новой личности.
- Первая reservation истекла из-за задержки инструмента. Это не время пользователя. Вторая передача выполнена свежим запросом: уведомление «Открыть матч» ведёт прямо в judge route и автоматически приобретает разрешённую сессию D. Первоначально ошибочное ожидание промежуточной кнопки «Судить» — ошибка автоматизации, не UI defect.
- Старый C вышел из judge UI после передачи; authoritative activeJudge стал D. Негативный POST старой сессией в пилоте не выполнялся; защита проверена отдельным GAP-012 gate.
- P01 ожидал несуществующий heading «Главная»; P19 ожидал имя без пробела, затем неверный регистр текста; P28 искал HTML labels вместо aria-labelledby, поэтому выбрал Анну в поле B. В отчёте фактический desktop состав B→A отражён явно. Это ошибки драйвера, не пользователя.
- Первый драйвер остановлен и перезапущен с ограничением времени локаторов. Его лог PASS означает завершение команды, а не PASS всего сценария. [runs.csv](runs.csv) — единственная интерпретация результата.
- p10-live — снимок pending, p17/p19/p25/p27 — возможные loading моменты. p33-2v2-roster-390 снят до прокрутки и является только контекстом; видимый состав — p34. p28 имена файлов с «a» не доказывают поле A; реальное значение/положение — JSON. p29 показывает наложение старого judge popup на A, а не чистый открытый селектор.
- Viewport PNG доказывает только видимую область. Нет заявлений о настоящем iPhone/Android, системной клавиатуре, WebKit, spoken screen reader или browser UI zoom200%. Эти проверки остаются явными ограничениями.
- Волuntary приглашения, сетевые ошибки, 360px и landscape не включены в завершённый основной pilot run; соответствующие пакеты выполняют их отдельно. Не переносить PASS основного пути на эти ветви.
