## Цель и границы

Аудит зафиксировал исходное состояние опубликованного table-tennis сервиса перед
этапом системного исправления. Проверены repository structure, требования,
архитектура, API/DB, backend/frontend defects, tests, deployment configuration и
live reachability. Аудит не менял внешние аккаунты, production DB или hosting.

Это не сертификат безопасности и не полный penetration test. Browser journeys со
всеми ролями и production data inspection не выполнялись; соответствующие области
помечены unknown/partial в [`../CAPABILITY_MATRIX.md`](../CAPABILITY_MATRIX.md).

## Вывод

Проект содержит значительный объём работающего domain/UI кода, но прежняя отметка
фаз `done` была сильнее evidence. Production reachability подтверждена, однако
release readiness — нет. P0-класс составляют secret exposure, hash disclosure,
temporary-password bypass, fail-open bootstrap, missing ownership/IDOR,
неприменённые domain invariants, неатомарный finish/stats/bracket, visibility,
start/stop authorization, потеря очка в UI и красный/flaky test gate.

Canonical backlog с полями evidence/repro/risk/verification/dependencies:
[`../BACKLOG.md`](../BACKLOG.md). Ниже — неизменяемое тематическое резюме.

## Security и authorization findings

- В example env находился live-looking Neon credential. Значение не включено в
  аудит. Внешняя ротация остаётся обязательной (`SEC-001`).
- Profile update сериализовал DB row с password hash (`SEC-002`).
- Temporary-password route allowlist проверял `includes` по raw URL (`SEC-003`).
- Render/bootstrap admin имел fail-open defaults/seed behavior (`SEC-004`).
- Production dependency graph имел high advisories (`SEC-005`).
- Match start и несколько tournament organizer mutations не проверяли ownership;
  participant removal имел cross-tournament IDOR (`SEC-006`, `SEC-007`).

## Correctness и concurrency findings

- Runtime body schemas не были системным gate; возможны invalid/duplicate roster,
  invalid side/winner/state transitions и side effects на invalid request
  (`DATA-001`).
- Match result, denormalized stats и tournament advancement выполнялись не в одной
  транзакции; параллельные ветки могли потеряться (`DATA-002`).
- Schema эволюционировала boot-time DDL без versioned migration ledger и полного
  набора constraints (`DATA-003`).
- Invitation/membership transitions имели duplicate/race risks (`DATA-004`).
- Полноценный void/immutable audit/compensation отсутствовал, а hard delete
  уничтожал исходные данные (`DATA-005`).
- Legacy V1 DE оставался declared playable при известном hang path (`DATA-006`).

## Product/UI findings

- Global match/tournament lists/details нарушали принятую visibility модель;
  tutorial isolation была неполной (`BUG-001`).
- Start/stop actor policy не соблюдалась (`BUG-002`).
- Rapid double `+1` мог потерять очко (`BUG-003`).
- Judge lock/live state, runtime 401, stale active screens, action errors и double
  submits имели воспроизводимые lifecycle gaps (`BUG-004..009`).
- Self-challenge, admin unblock/self action, onboarding и notification semantics
  были неполны/сломаны (`BUG-010..013`); ranking periods считались по UTC вместо
  принятой Europe/Moscow границы (`BUG-014`).
- Home, profile, history, ranking, matches/judge, tournament, teams,
  notifications, onboarding/help и admin реализовали только часть исходного PRD
  (`GAP-001..010`).
- Touch targets, contrast, safe-area/layout, semantics и bracket navigation не
  прошли реальную browser/a11y верификацию (`GAP-011`).

## Operations/testing/docs findings

- OpenAPI/code/target API spec расходились (`OPS-001`).
- Structured observability и DB readiness отсутствовали (`OPS-002`).
- Backup/seed safety и production recovery evidence были недостаточны (`OPS-003`).
- Package/OpenAPI/deploy/changelog versions не позволяли доказать deployed commit
  (`OPS-004`).
- Free Render cold start наблюдался, но отдельного bounded wake-up UX не было
  (`OPS-005`).
- Full tests были красными/flaky; critical browser/E2E, axe/visual/two-client
  coverage отсутствовало (`TECH-001`, `TECH-002`).
- Login limiter считал успешные логины и имел per-process/unbounded-state flaws
  (`TECH-003`).
- Requirements manifest v2.0 от 2026-07-20 не соответствовал изменённым файлам и
  не мог считаться текущей integrity map. Он сохранён как historical/deprecated.
- VERSIONING указывал 1.4.0 при package 1.10.1; status/changelog смешивали planned,
  implemented и deployed; Figma ошибочно объявлялась активным эталоном.

## Принятые во время аудита продуктовые решения

Зафиксированы ADR D17–D21:

- active event: organizer + participants + current active judge; completed event:
  все active non-blocked club users;
- start: creator/organizer; early stop: creator/organizer или current active judge;
  cancel оставлен открытым;
- erroneous finished result: void only + immutable audit + stats compensation,
  без hard delete; actor/approval оставлены открытыми;
- UI/calendar boundaries: Europe/Moscow; absolute timestamp storage UTC как
  техническая convention;
- free Render wake-up ≤60s только с явным loading/waking state, timeout и Retry;
  warm SLO не смягчается.
