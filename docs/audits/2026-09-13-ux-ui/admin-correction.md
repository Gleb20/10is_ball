F-ADMIN-003 — наблюдение применённого reset с потерянным ответом подтверждено. Повтор POST не выполнялся, потеря второго пароля/гонка двух reset не воспроизведена. Точная спецификация принята отдельно: reset-review.json и обязательный admin-reset-correction.md. Исходный marker-протокол остаётся отозванным.

F-ADMIN-004 — обычный отказ live detail соответствует D17. Доступ к API force-close не означает разрешение открыть обычную карточку или глобальный список активных матчей. До ответа новое право чтения не принято.

## Согласованный минимальный каталог и карточка

Каталог остаётся `/admin`, явная ссылка «К профилю». Заголовок → поиск и статус → число результатов → список; «Добавить пользователя» раскрывает одну inline форму перед списком, по умолчанию закрытую. Закрытие с изменениями требует подтверждения; pending не закрывает форму. Один writer сохраняет текущий payload, one-time password, stale-session guards и все операции. На desktop сохраняется существующий shell: отдельный глобальный responsive redesign не входит в задачу.

Имя пользователя ведёт в `/admin/users/:id`. В строке только это основное действие и «Действия»: обычный Button с aria-expanded/controls раскрывает inline группу обычных кнопок. Это не ARIA menu; Tab проходит кнопки, Escape закрывает и возвращает фокус. Одновременно раскрыта одна строка. Доступные команды выводятся по текущим actor/target guards; существующие именованные подтверждения сохраняются. Не придумывать отсутствующий экспорт Menu из ui.tsx.

Карточка: «К пользователям» → имя/роль/статус и существующие AdminUser поля → «Редактировать» с текущей формой → «Действия» → история. Доступ только active admin; смена роли/блокировка/401 немедленно закрывает частные данные. Поля email и аватар подчиняются существующим ограничениям. Никаких чужих матчей или секретов.

### Минимальный read contract истории

`GET /api/v1/admin/users/:userId` возвращает существующий allowlisted AdminUser, не сырой users row. `GET /api/v1/admin/users/:userId/audit?cursor=...` возвращает `{items,nextCursor}`. UUID path и opaque cursor валидируются; фиксированный limit=20; порядок `(createdAt DESC,id DESC)`, cursor привязан к target и последней паре. Никакого offset-зависимого дублирования при новых записях. На каждом запросе requireAdmin; отсутствующий target 404; обычный/blocked actor 403 либо текущий auth response.

Item: `id, createdAt, actor:{id,displayName}|null, action, changedFields:string[]`. Только entityType=user и exact entityId; allowlist действий `user.created`, `user.updated`, `user.role_changed`, `user.blocked`, `user.unblocked`, `user.password_reset`, `admin.bootstrap_provisioned`. Неизвестные действия не раскрывать. Null actor подписать «Система / автор не указан», не выдумывать человека. Человеческие имена берутся из текущего account record, не выдавать их за исторический snapshot. Отсутствующая запись actor не ломает историю.

`meta` целиком не возвращается. changedFields фильтруется по существующим разрешённым именам полей профиля/role; значения, password/hash/token/cookie/session/request metadata не возвращаются. Событие означает записанное действие; поле outcome не выдумывать, схема его не хранит. Не показывать неподтверждённые failures как успешные события. Дата — Europe/Moscow с явной подписью МСК; без изменения серверного UTC.

Существующие audit rows не переписываются. Отдельная миграция не обязательна: индекс `(entity_type,entity_id,created_at,id)` добавлять только с доказанной необходимостью и проверкой. Новые mutations и права не вводятся. В будущем после successful существующей операции перечитать заголовок и первую страницу; старые страницы сбросить, draft не стирать до подтверждённого успеха. Ошибка чтения имеет локальный Retry GET; нет auto mutation.
