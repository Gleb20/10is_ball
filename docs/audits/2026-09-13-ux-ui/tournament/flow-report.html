Tab-10 TOURNAMENT — User Flow Report

2026-09-14 · Экспертный аудит создания, состава, сетки, ролей и завершения; без изменений приложения

userflowflow-formsflow-navigationflow-errorsflow-sharinginterface-design

Summary

Семь собственных Chromium-runs подтвердили целостный основной flow и серверные границы ролей. Proposed flow не меняет продуктовую модель: он защищает три consequential actions, возвращает составу первичный приоритет, скрывает преждевременный результат и добавляет один уровень обзора сетки. Это экспертная спецификация; пользовательские метрики и ошибки реального человека не наблюдались.

As-is: создать комнату и подготовить сетку

Pattern source: flow-forms + flow-navigation · Entry: вкладка «Начать» → «Турнир»

Steps

  1. 1Создание

    Организатор задаёт название, формат, своё участие и consent policy. На 390 форма не имеет горизонтального overflow.

    Primary action: Создать → detail в collecting

    Если consent выключен → состав можно заполнять напрямую.
  2. 2Настройки и lifecycle actions

    До состава показаны правила, policy note, «Построить сетку» и «Отменить турнир» равного визуального уровня.

    Primary action: неоднозначен до заполнения состава

  3. 3Состав

    Active roster, invitations и add controls. В direct-mode registered add всё равно вызывает native confirm.

    Primary action: Добавить в состав → confirm → roster refresh

    Consent/admin/generated → confirm сообщает override/regeneration; это нужные ветви.
  4. 4Построение

    Algorithm Dialog выбирает compact/power-of-two; V2 отображает BYE и сохраняет seed order.

    Primary action: Построить сетку → bracket_generated

Proposed: состав ведёт к готовой сетке

Pattern source: flow-forms + flow-navigation · Entry unchanged

Steps

  1. 1Создание без новой сложности

    Текущая форма и defaults сохраняются.

    Primary action: Создать → collecting room

  2. 2Состав и приглашения

    После компактной сводки правил сразу находится roster. Direct organizer add в collecting не требует confirm.

    Primary action: Добавить игрока/гостя → обновлённый roster

    Consent/admin/generated → именованное подтверждение сохраняется.
  3. 3Готовность и сетка

    После roster появляется основное действие построения; cancel уходит в отдельное «Управление турниром».

    Primary action: Построить сетку → algorithm Dialog → bracket

  4. 4Защищённые последствия

    Cancel/dissolve/generated-withdraw называют объект и эффект; Escape/secondary не меняют state.

    Primary action: Подтвердить точное действие → persisted transition

As-is / proposed: играть и ориентироваться в сетке

Pattern source: flow-navigation · Entry: tournament detail для participant/organizer

Steps

  1. 1Найти задачу

    Participant видит «Ваши матчи»: следующий link, затем текущий link после старта. После победы label продвигается W0_0 → W1_0.

    Primary action: Текущий/Следующий матч → match detail

  2. 2Осмотреть bracket

    Стрелки и Home/End работают, region имеет focus outline. На 100% уменьшение недоступно; 125/150 только сокращают обзор.

    Proposed action: − до 75% → обзор большего фрагмента при сохранении текста

  3. 3Завершение

    Finished показывает чемпионат, сетку и корректный top3. Proposed: только terminal states показывают «Итоги».

    Primary action: Открыть → сыгранный матч

    Stopped → причина и незавершённые места `—`; никакой выдуманной расстановки.

Role sharing and recovery

Pattern source: flow-sharing + flow-errors · Entry: direct URL / invitation / notification

Steps

  1. 1Organizer

    Настройки, roster, bracket lifecycle, start/stop/cancel. Сервер остаётся источником прав.

    Primary action: следующее действие текущего статуса

  2. 2Participant

    Readonly tournament context, own current/next match, допустимое судейство. Generated withdraw требует предупреждения.

    Primary action: Открыть свой матч

  3. 3Scoped admin

    Только каталог registered users и подтверждённое ручное добавление; settings/start/guest скрыты.

    Primary action: Добавить в состав → named override confirm

  4. 4Outsider / failure

    Direct URL даёт «Ошибка — Недостаточно прав» и Refresh. Proposed mutation error остаётся рядом с исходным block/Dialog.

    Recovery: Обновить → повторный authoritative GET
