# WO4 / GAP-034 — предварительная runtime-инвентаризация и целевой срез

**Статус:** target для рассмотрения координатором, без реализации и без приёмки Stage 3. База — принятый локальный WO3 R2 manifest SHA-256 `54860798d7c0744a838e7d1b299a2f44ea34f03c7e6176f7663afe51adc030fd`. Его 124 хеша были сверены с рабочим деревом перед проходом; продуктовые файлы этим проходом не менялись. Область — U01-DETAIL-002/a01 и U01-JUDGE-003/a03, GAP-034, AT-UI-STATUS-001, D36/D37. Первичный пользовательский комментарий — качественная реакция одного человека на кадры; частота ошибочных нажатий не измерялась.

## Как получено

Принятый R2 собран во временный `dist`, открыт локальным Chromium через `vite preview`. Все ответы `/api/v1/*` перехвачены синтетическими данными. 28 контекстов на 360/390/1440 px, обычной светлой поверхности, предпочтении ОС dark и тёмном Judge. Все 28 маркеров загрузились, `pageerror=[]`, неизвестных API-запросов 0, горизонтального переполнения viewport 0. Есть 47 снимков: полный viewport и, для длинных страниц, прокрутка к первому бейджу. Файлы: [runtime.json](./runtime.json), [chip-contract.json](./chip-contract.json), [скрипт](/private/tmp/tab10-wo4-inventory.mjs), [лог](/private/tmp/tab10-wo4-preliminary-run.log). Это DOM/визуальные факты локальной сборки с mock GET, **не** проверка серверных прав, реальной БД, опубликованного стенда или физического телефона.

## Воспроизведённый дефект общего элемента

`apps/web/src/patterns.tsx` использует ic-kit `Chip` без `startIcon`; библиотека добавляет декоративный CaretDown. На всех 7 прямых consumers (`HomePage`, `MatchesPage`, `MatchDetailPage`, `TournamentsPage`, `TournamentDetailPage`, `HistoryPage`, `AdminPage`) фактические chip — `SPAN`, `role=null`, `tabIndex=-1`, высота 24 px, текст сохранён, иконка `aria-hidden=true`, но CSS задаёт `cursor:pointer` и hover-фон. В 24 последовательных Tab на Home, detail и admin ни один chip не получил фокус; Home ссылкам карточек фокус достался. Пары сплошного текста/фона дали ориентировочный контраст 7.79:1 (purple), 4.90:1 (green), 6.36:1 (red); нейтральный полупрозрачный фон требует композиции с фактической подложкой. Это количественная проверка текущих пар, не заявка менять палитру.

Контракт `startIcon=false` отдельно проверен в Chromium на фактическом ic-kit render: default — span с `aria-hidden` стрелкой; false — тот же span и текст, стрелки нет ([JSON](./chip-contract.json)). Сама стрелка не доступна screen reader, но визуально напоминает раскрытие; pointer/hover усиливают этот намёк. Реакция U01 на один кадр таким образом подтверждается для общего `StatusChip` в локальном runtime; восприятие всех локальных Chip пользователями не измерено.

## Приёмка будущего sample и откат

- **Given** доступный waiting / in progress / pending confirmation / terminal match или tournament статус и active/blocked user, **When** открыты Home, список, detail, history или admin, **Then** прежний текст/цвет остаются, у `StatusChip` нет декоративного caret, собственного hover/pointer и tab stop. Список/карточка-ссылка сохраняет переход и keyboard focus; standalone status не запускает действие.
- **Given** выбранный фильтр или доступное действие рядом со статусом, **When** пользователь идёт клавиатурой и активирует его, **Then** `pressed/checked`, focus и disabled относятся к управляющему элементу, а не к persisted status; права не расширяются.
- **Given** обычный finished match с одинаковыми displayName и `winnerSide=B`, **When** открыт Home, **Then** трофей остаётся у стороны B, а score и текст не меняются. D37 скрытые приглашения не появляются в Home/notices/count.
- **Given** loading/empty/error на 360/390/desktop, **When** состояние меняется, **Then** текст и recovery control остаются доступными; статус не маскирует alert или live message. OS dark не создаёт смешанную тему, immersive Judge остаётся читаемым.
- **Given** общий chip и прямые consumers, **When** прошли focused component/package checks и реальный браузерный проход 360/390/desktop, **Then** сохранены все label, card links, фокус и отсутствие overflow. Контраст проверяется на фактическом фоне; для нейтральной подложки требуется композиция. Отдельные Stage 6/8/9/10/11 продолжают свою browser acceptance.

**Проверки после разрешения:** focused `patterns`/Home tests, типизация и тесты web package, браузерная матрица всех семи прямых consumers с keyboard/focus, 360/390/desktop, empty/error и локальным тёмным Judge regression; контраст фактических фонов. Если изменение CSS затрагивает общую библиотеку или пакеты, расширить до `pnpm run ci` согласно AGENTS.md. Перед правкой снять новый snapshot/diff, затем сравнить с R2. **Откат:** вернуть только будущий scoped delta `patterns.tsx`/`styles.css`/focused tests, повторить браузерный контроль существующего chip; R2 frozen manifest и материалы WO1–3 остаются нетронутыми. Исходное состояние и набор 47 снимков сохранены в `/private/tmp`.

Эти проверки принадлежат соответствующим последующим этапам или будущей приёмке sample. Текущий проход не завершает GAP-034 и не даёт разрешения на релиз.
