Итог

Основной путь судьи проходит и сохраняет правильное серверное состояние: rapid input, Undo, correction, handover, ownership, pending/continue/finish, no-show и stop. Главный риск находится в ветке неопределённого результата: сервер уже применил очко и UI это отобразил, но текст предлагает повторить действие. Клавиатурная коррекция также теряет focus при входе и возврате.

Предлагаемый flow не меняет права и не добавляет автоматический retry. Он делает один следующий шаг главным, различает тот же телефон и другое устройство, а recovery делит на подтверждённую запись, подтверждённый отказ и неизвестный результат.

Flow: начать и вести счёт

Источник паттерна: flow-sharing + interface-design · Вход: MatchDetail в ожидании

Текущий путь

  1. 1MatchDetail: ожидание

    Creator видит пустой журнал и семь действий; «Старт» и «Судить» одинаково выделены.

    Competing actions: Старт / Судить

  2. 2Захват и setup

    Судья выбирает первую подачу и стороны. При сохранении кнопка pending, но radios/swap остаются изменяемыми.

    Pending mismatch → evidence `j02`; dedup BUG-026.
  3. 3Счёт

    Две большие стороны, +1, подача, Undo, Ещё. Два быстрых тапа входят в видимую очередь и сохраняются по порядку.

    Основное действие: +1 → authoritative score

  4. 4Исправление

    «Ещё» → correction. Данные сохраняются, но keyboard focus падает в BODY на входе и выходе.

    Focus failure → F-JUDGE-002.
  5. 5Предварительный результат

    Победное условие блокирует +1 и показывает Confirm / Continue. Continue возвращает live; Confirm делает result read-only.

    Основное действие: Подтвердить результат

Предлагаемый путь

  1. 1Один следующий шаг

    Для creator со свободным слотом — «Начать и вести счёт»; остальные действия вторичны и permission-aware.

  2. 2Честный submitted snapshot

    После Start все payload controls заморожены; UI показывает отправленные стороны и подачу.

  3. 3Операционное ведение

    +1 остаётся главным; «Отменить очко» и «Действия» заменяют технические Undo/Ещё.

  4. 4Correction с focus contract

    Focus входит в heading/first field, остаётся при ошибке и возвращается к invoker.

  5. 5Проверка результата

    Confirm — primary; Continue — secondary; результат сообщает authoritative score и следующую игру по роли.

Flow: тот же телефон или другое устройство

Источник паттерна: flow-sharing · Вход: активный JudgePage

  1. 1Тот же телефон

    Никакой идентификации: счёт продолжает вести текущий аккаунт. Человек, который держит телефон, не меняет auth/session.

    Основное действие: продолжить счёт

  2. 2Другое устройство

    Действия → «Передать на другое устройство» → выбрать активного пользователя.

    Directory loading/error сейчас не честны → dedup BUG-025.
  3. 3Резервирование

    Старый судья теряет mutation rights; выбранный target приобретает их один раз. Другие и вторая сессия того же пользователя получают read-only recovery.

  4. 4Release

    «Завершить ведение и выйти» ждёт один best-effort release; destination показывает success/warning. Crash/tab close полагаются на TTL.

Flow: ошибка начисления и восстановление

Источник паттерна: flow-errors · Вход: запись очка

Сейчас

  1. 1Known no-write

    503 оставляет authoritative score и показывает error; красный текст 2.58:1 — BUG-024.

  2. 2Unknown outcome

    Server applies point, response is lost, refresh displays changed score, but alert still says “repeat”.

    Unsafe instruction → F-JUDGE-001.
  3. 3Version conflict

    Queue stops, explicit stale message appears, authoritative score refreshes. No automatic replay.

  4. 4Offline

    Last state stays visible, but the same generic repeat text appears and no Refresh/Retry action exists.

Предложение

  1. 1Pause and preserve context

    Keep score/serve visible; pause score mutations; announce connection/outcome state.

  2. 2Read-only сверка

    Один раз получить authoritative state без повторной отправки score intent.

    Основное действие: Обновить счёт

  3. 3Определить исход

    Exact intent key найден → запись подтверждена; server rejection → отказ подтверждён; иначе ручная сверка без инструкции повтора.

  4. 4Resume deliberately

    Only after authoritative render and operator acknowledgement; stale queued taps are not replayed.

Открытые вопросы и отложенные проверки

  • Implementation synthesis must choose whether `Начать и вести счёт` composes current start/acquire calls or remains a hierarchy/copy-only change; no permission may expand.
  • Текущий GET уже отдаёт exact idempotency key/event log: наличие ключа доказывает запись, раннее отсутствие — ещё не отказ. Если дальнейший API-контракт понадобится для более быстрого определения, это отдельное решение.
  • Physical devices, WebKit, browser zoom 200%, and spoken AT remain parked verification, not implicit PASS.
